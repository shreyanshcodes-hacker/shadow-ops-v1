## 1. Truthful Cloud Integration Status

In accordance with strict cybersecurity engineering ethics, ShadowOps distinguishes between functionality that has been **mathematically verified in automated hermetic tests** and integrations that remain **unverified against live third-party cloud infrastructure**.

The table below reflects the exact operational state of every cloud dependency:

| Cloud Integration / Component | Hermetic / Local Status | Live Cloud Status | Risk Level for Pilot | Operational Pilot Mitigation |
| :--- | :--- | :--- | :---: | :--- |
| **Google Firebase Authentication** | **VERIFIED** (Hermetic JWT parsing & signature check) | **UNVERIFIED** (Live token verification with Google auth servers) | Medium | In production, unsigned fallback is strictly disabled (`settings.is_production`). Pilot requires supplying real Firebase Admin service account keys. |
| **Supabase PostgreSQL & RLS** | **VERIFIED** (Application-level tenancy & syntax audit) | **UNVERIFIED** (Live database-tier RLS enforcement) | Low | Application-level queries explicitly filter by `workspace_id`. In pilot, live Supabase instance enforces both application and DB RLS. |
| **Google Gemini & Grok AI** | **VERIFIED** (Provider abstraction, fallbacks, structured schemas) | **UNVERIFIED** (Live token quotas & latency under load) | Low | AI cannot modify findings or override deterministic risk scores. Fallback deterministic models activate if AI is unavailable. |
| **SMTP Transactional Alerts** | **VERIFIED** (Safe degradation & template rendering) | **UNVERIFIED** (Live email inbox delivery & SPF/DKIM) | Low | System safely operates in in-app notification mode when SMTP credentials are not configured. |
| **n8n Workflow Automation** | **VERIFIED** (Anti-SSRF validator & disabled-by-default flag) | **UNVERIFIED** (Live webhook execution) | Negligible | Kept strictly disabled (`N8N_ENABLED=false`) until explicitly enabled by pilot customer. |
| **Railway Hosting** | **VERIFIED** (Local container builds & health probes) | **UNVERIFIED** (Live Railway cluster deployment) | Low | Readiness and liveness probes `/health/ready` and `/health/live` manage deployment health. |

## 2. Technical Limitations & Divergences

### 2.1 SQLite vs PostgreSQL
- **Local Dev / Unit Tests:** Uses SQLite (`aiosqlite`) for instant, dependency-free execution.
- **Production:** Uses Supabase PostgreSQL.
- **Divergence:** SQLite does not natively enforce PostgreSQL Row Level Security (RLS) policies or strict JSONB binary index operators (`@>`). In SQLite mode, tenancy is enforced at the application tier. All SQL migrations have been audited and verified for PostgreSQL compatibility in `backend/tests/test_stage12_migrations_audit.py`.

### 2.2 Semgrep CLI Dependency
- The scanner requires the `semgrep` binary to be installed on the host or inside the container.
- If the binary is missing, `ScanService` catches the exception and transitions the scan status to `failed` with a clear diagnostic message, rather than crashing the backend.
- The root `Dockerfile` and development environment packages include Semgrep CLI.

### 2.3 Email Delivery Degraded Mode
- When SMTP environment variables (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`) are omitted, `EmailAdapter` records delivery as `not_configured`.
- Notifications remain visible and interactable in the web frontend notification inbox (`/notifications`).

## 3. Controlled Pilot Acceptance Conditions

Pilot participants and internal operators agree to the following operational parameters:
1. **Supervised Access:** Early deployments must be monitored by designated engineering liaisons.
2. **Credential Provisioning:** Pilot operators must configure valid credentials in `.env` before attempting live scans or AI remediation workflows.
3. **No Automatic Code Push:** Patches generated by ShadowOps are presented as unified diff previews and require human engineering review before deployment to production repositories.
4. **Audit Log Monitoring:** SRE must review `/api/v1/health/ready` and `event_outbox` periodically to verify zero quarantined events.

## 4. Path to General Availability (GA)

To remove the "Controlled Pilot" classification and achieve **Ready for Production (GA)**:
- [ ] Connect and verify a live production Firebase project with custom tenant domains.
- [ ] Deploy migrations to a live Supabase PostgreSQL database and verify RLS enforcement using dual-session psql scripts.
- [ ] Conduct live load testing on Gemini 1.5 Pro structured outputs with 50+ concurrent requests.
- [ ] Verify SPF, DKIM, and DMARC passing on emails sent through SendGrid/Resend.
- [ ] Run a live deployment to Railway and execute zero-downtime healthcheck validations.
